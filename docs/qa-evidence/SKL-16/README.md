| AC2: Versioning rules in the skill | Verified | The skill's `## Versioning` section tags the commit the promotion merged on `profile.git.release_branch`, after the merge and before any production deployment, and pushes the tag to `origin`; under `promotion: none` it tags the integration-branch head that readiness verified. The tag is annotated and signed when `profile.git.signed_commits` is true, and a signing failure stops rather than falling back to unsigned. The component comes from the promotion PR body's own standalone `Release-Type: major|minor|patch` line, defaulting to `patch` when absent, and `whole-branch` selects the highest component any promoted story requests. Semver uses prior release-branch tags matching `v<major>.<minor>.<patch>`, `v0.1.0` with none, otherwise the highest such tag with the selected component incremented and every component to its right reset to zero (`v2.3.4` examples `v3.0.0`/`v2.4.0`/`v2.3.5`). Calver uses the UTC `YYYY.MM.DD` date, appending `.N` at the lowest integer N at or above 1 whose tag is free. An existing tag stops the step with the collision reported and is never moved or force-updated, and an unset `profile.release.versioning` stops the step with the release reported untagged. |
| AC3: Release-notes rules in the skill | Verified | The skill's `## Release notes` section generates notes from the issue set `Release readiness` enumerates with each issue's merged PRs, or under `promotion: none` from every story awaiting closure with its merged PR, and publishes to `profile.release.notes` immediately after the tag is confirmed on `origin` and before the deployment hand-off, reporting the published URL (each comment URL for `tracker-comment`). `github-release` creates a GitHub Release at the versioning tag with the notes as its body; `tracker-comment` posts one comment on each promoted issue's tracker record with that issue's own entry and the tag, and stops and asks when the tracker cannot be written. An unset `profile.release.notes` stops the step, and `github-release` with an unset `profile.release.versioning` stops and reports that a GitHub Release requires a tag without publishing under an invented tag. ## Scope and limits

The delivered contract is prose guarded by phrase assertions, so semantic drift outside the asserted phrases is not covered by a test; the story records that as an open risk, and this QA verified the prose itself against each acceptance-criteria clause rather than inferring it from the tests alone.
No live release tag was created and no release notes were published: this repository ships no releasable artifact, so AC2 and AC3 are verified as the written procedure the persona follows, including reading the skill's own Promotion section as the source of the `Release-Type` line.
Runtime agent compliance with the procedure is outside the story's stated scope.
